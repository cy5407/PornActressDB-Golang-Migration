**修復日期**：2025-11-16 01:30  
**版本**：v5.4.3+  

---

## 問題描述

修復後的爬蟲變得太嚴格，導致：
- ❌ 許多頁面找不到女優資訊
- ❌ 出現大量「未找到女優資訊」警告
- ❌ 系統可用性下降

---

## 根本原因分析

### 初始問題
- 261 位女優都是垃圾文本（頁面導航、分類名稱等）

### 第一次修復的過度反應
- 只依賴 `rel="tag"` 且 `/av-actress/` 連結
- 許多 AV-WIKI 頁面不提供這樣的結構化連結
- 導致無法找到真實的女優資訊

---

## 解決方案：分層提取策略

### 優先級（四層回退機制）

```
第1層: tag 連結（最可靠）
  ↓ 如果沒有找到
第2層: actress-name class
  ↓ 如果沒有找到
第3層: 文章內的 tag 連結
  ↓ 如果都沒有找到
第4層: 智能文本掃描（受限制）
```

### 關鍵改進

#### 1. 無結果頁面檢測
```python
# 檢測搜尋無結果
if any(keyword in page_text for keyword in [
    '見つかりませんでした',  # 未找到
    'No results',
    '検索ワードに一致する記事は見つかりませんでした',
]):
    return empty_results
```

#### 2. 改進的文本掃描
- 尋找包含「出演」「女優」等關鍵詞的行
- 只掃描文本的前 30% 和後 20%（避免導航區域）
- 限制最多 15 位女優
- 更強的垃圾文本過濾

#### 3. 增強的驗證
新增排除關鍵詞：
- 否定詞：ありません, ない, いない, etc.
- 感嘆詞：です, ます, ました, etc.
- 代詞和連接詞：こと, もの, ので, から, etc.

## 最佳實踐

### ✅ 應該做的
1. 優先使用結構化資訊（tag 連結）
2. 逐層回退，而不是一次性失敗
3. 對文本掃描結果施加限制
4. 檢測特殊頁面（無結果、錯誤等）
5. 使用多個過濾層來去除垃圾

### ❌ 不應該做的
1. ❌ 無差別掃描整個頁面文本
2. ❌ 依賴單一的資訊來源
3. ❌ 無限制地接受提取結果
4. ❌ 忽視頁面語義（無結果頁面等）
5. ❌ 過度信任正則表達式
