# 20260526-分類搬移保留原始檔名-Task

> 狀態：待實作
> 來源：2026-05-26 code review 發現
> 範圍：Wails 前端分類搬移 destination 命名與 studio move guard 小修

## 目標

女優分類搬移是「分類到資料夾」，不是 rename-and-move。前端目前用 `r.code + ext`
重建目的檔名，會把 `KUSE-042-1.mp4` / `KUSE-042-2.mp4` 這類 multi-part 檔案壓成同一個
`KUSE-042.mp4`，導致不必要的 conflict，甚至在 `overwrite` 策略下造成資料遺失。

修正後應保留原始 basename，只改變所在資料夾：

```text
C:\in\A\KUSE-042-1.mp4 -> <output>\夏目響\KUSE-042-1.mp4
C:\in\A\KUSE-042-2.mp4 -> <output>\夏目響\KUSE-042-2.mp4
```

同時修正 `studioMoveGuard` 對合法 `source == destination` no-op skip 的誤擋。

## 必修 1：分類搬移保留 basename

目前問題點：

```typescript
// wails-app/frontend/src/App.tsx
destination: `${outputDir}\\${actress}\\${r.code}${pathExt(r.path)}`
```

請改成使用原始 basename，例如抽出 helper：

```typescript
function basenameOf(path: string): string {
  const normalized = path.replace(/\//g, '\\');
  return normalized.split('\\').pop() || path;
}
```

然後 destination 改為：

```typescript
destination: `${outputDir}\\${actress}\\${basenameOf(r.path)}`
```

要求：

- 不改 scan / extractor / SQLite / Wails backend contract。
- 不新增 rename policy。
- 不改 conflict strategy 語意。
- 一般單檔也要保留原始 basename。
- multi-part 同 code 不同 basename 必須產生不同 destination。

## 必修 2：same-path skip 不應觸發 studio move guard

Go 端 `MoveFile` 對 `source == destination` 的語意是合法 no-op：

```go
result.Skipped, result.Success = true, true
```

`studioMoveGuard` 不應把這類 skip 視為「上一輪 BatchMove 有未處理殘留」。請在 guard 中排除
`normalizePath(source) == normalizePath(destination)` 的 skipped result。

要求：

- `source == destination` 且仍留在 `scanResults` 時，`blocked` 必須是空陣列。
- 真正的同名跨目錄 skip 仍要 block。

## 建議影響檔案

- `wails-app/frontend/src/App.tsx`
- `wails-app/frontend/src/lib/studioMoveGuard.ts`
- `wails-app/frontend/scripts/studio-move-guard.test.mjs`
- 若抽 helper，優先放在 `wails-app/frontend/src/lib/`，避免塞更多 inline 邏輯進 `App.tsx`。

## 測試要求

至少補以下測試：

1. 同 code 不同 basename：
   - `KUSE-042-1.mp4`
   - `KUSE-042-2.mp4`
   - 產生不同 destination，且 basename 原樣保留。
2. 一般單檔：
   - `STARS-707 4K.mp4` 或含空白的 basename 也要原樣保留。
3. `studioMoveGuard`：
   - `skipped=true`
   - `success=true`
   - `source == destination`
   - source 仍在 `scanResults`
   - 預期 `blocked = []`。
4. 既有同名跨目錄 skip case 必須仍然 block。

若前端沒有正式 test runner，沿用現有 `wails-app/frontend/scripts/studio-move-guard.test.mjs`
的 `esbuild + node:assert/strict` 模式即可；不要為此引入 Vitest / Jest。
