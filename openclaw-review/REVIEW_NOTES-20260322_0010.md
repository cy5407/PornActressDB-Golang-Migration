## 嚴重問題清單

### 問題 1（BUG）：go_accelerated_db.py 的 Python 3.10 相容性未完整修復

- **檔案**：`src/models/go_accelerated_db.py`
- **行號**：283
- **問題代碼**：`from datetime import UTC, datetime`
- **症狀**：在 Python 3.10 環境下，呼叫 `add_or_update_video()` 且影片不存在時，
  觸發 `ImportError: cannot import name 'UTC' from 'datetime'`
  程式直接崩潰（非 graceful error）。
- **影響範圍**：
  - `classifier_core.py` L128：`_persist_code_result()` → `add_or_update_video()`（每批搜尋必呼叫）
  - `classifier_core.py` L1116：片商分類流程
  - 只要搜尋到新影片（尚未在 DB 中），就會觸發此 bug
- **建議修復**：
  ```python
  # 改為：
  from datetime import datetime, timezone
  UTC = timezone.utc
  # 或更簡單，直接從已修復的 json_types 導入：
  from src.models.json_types import UTC
  ```

## 非嚴重警告清單

### 警告 1：db_get_video 對「影片不存在」記錄 error 而非 debug

- **檔案**：`src/services/go_bridge.py`
- **詳情**：Go CLI 回傳「找不到影片」時以 exit code 1 結束，Python 側視同 bridge fault，
  以 `logger.error` 記錄。但搜尋新番號時「不存在」是正常業務情況，可能造成 log 雜訊。
- **建議**：在 `except GoBridgeError` 中額外檢查 stderr 是否含「找不到」/「not found」，
  若是則降為 `logger.debug`。

### 警告 2：journal replay 與 omitempty 欄位清空不一致

- **檔案**：`pkg/database/journal.go`
- **詳情**：`UpdateVideo` 寫入的 JSON 不包含空字串的 omitempty 欄位
  （如 `original_filename`, `file_path`, `search_method`, `studio_code`）。
  若這些欄位由非空改為空，in-memory 立即正確，但 journal replay 後不會清除舊值。
  此問題僅在意外崩潰靠 journal 還原時才顯現，低機率且低影響。
- **建議**：若有意清空這些欄位，改用 `UpdateVideoFields({"field": ""})` 傳明確 null/empty。

### 警告 3（Pre-existing）：db merge 子命令 FlagSet 雙重解析問題

- **檔案**：`cmd/scanner/main.go`
- **詳情**：`dbCmd` 最上方的 `fs.Parse(args[1:])` 遇到 merge 特有的 `-source` flag 會 exit。
  這個問題在引入 `db merge` 命令時就存在，與本次修復無關。
- **建議**：`db merge` 應在 subcommand dispatch 之前不解析 flags，或用不同的架構（如 cobra）。
