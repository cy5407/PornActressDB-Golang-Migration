# GUI 打包修復報告
**日期**：2026-04-03
**對象**：非工程背景使用者
**問題類型**：功能缺失（Go 加速在打包版 GUI 中無法運作）

---

## 問題是什麼？

這個專案有兩個主要程式：

| 程式 | 用途 |
|------|------|
| `女優分類系統.exe` | 給你用的圖形介面（GUI），放在 `dist` 資料夾 |
| `classifier.exe` | 在背後負責加速運算的引擎，放在專案根目錄 |

**問題**：`女優分類系統.exe` 打包時，沒有把 `classifier.exe` 一起帶進去。
就像你帶了汽車（GUI）出門，但把引擎（classifier.exe）留在家裡——車子會動，但跑得非常慢，Go 加速功能完全失效。

---

## 為什麼會這樣？

### 打包工具的運作方式

我們使用一個叫 **PyInstaller** 的工具，把 Python 程式碼打包成一個 `.exe` 檔案，方便你直接點兩下執行，不需要安裝 Python。

打包時，PyInstaller 會依照一份「清單」（`.spec` 檔案）決定要把哪些檔案打進去。

### 原本的清單內容

```
打包清單：
✅ src 資料夾（程式邏輯）
✅ config.ini（設定檔）
✅ major_studios.json（片商資料）
✅ studios.json（片商資料）
❌ classifier.exe ← 這個被漏掉了！
```

### 找不到引擎的連鎖效應

GUI 啟動後，會去找 `classifier.exe`。它的尋找順序是：

1. 程式自身所在的資料夾
2. 你開啟程式時的目錄
3. 系統環境變數 PATH

但打包後的 `女優分類系統.exe` 是一個「自給自足」的程式，它執行時會解壓到電腦的**暫存資料夾**（一個隨機產生的臨時位置），而不是 `dist` 資料夾。原本的尋找邏輯完全沒考慮這個暫存位置，所以 `classifier.exe` 永遠找不到。

---

## 我們做了什麼修復？

### 修復 1：把引擎加進打包清單

**修改的檔案**：`女優分類系統.spec`

**修改前**：
```
binaries = []   ← 空的，沒有附帶任何執行檔
```

**修改後**：
```
binaries = [('classifier.exe', '.')]   ← 把 classifier.exe 一起打包
```

**白話說明**：就像出門前記得把引擎也帶上車。

---

### 修復 2：告訴 GUI 去暫存資料夾找引擎

**修改的檔案**：`src/services/go_bridge.py`

打包後的程式執行時，所有附帶的檔案會被解壓到一個叫 `_MEIPASS` 的暫存資料夾。我們在尋找路徑的最前面，加上了這個暫存位置。

**修改前的尋找順序**：
1. 專案根目錄
2. 當前目錄
3. 系統 PATH

**修改後的尋找順序**：
1. ⭐ **PyInstaller 暫存資料夾**（新增）← 打包版 GUI 會在這裡找到
2. 專案根目錄
3. 當前目錄
4. 系統 PATH

**白話說明**：就像告訴司機「引擎在後車廂，不是在家裡」。

---

## 修復後的效果

| 情況 | 修復前 | 修復後 |
|------|--------|--------|
| 直接用 Python 執行（開發模式） | ✅ 正常 | ✅ 正常 |
| 點兩下 `dist/女優分類系統.exe` | ❌ Go 加速失效，跑很慢 | ✅ Go 加速正常 |

---

## 你需要做什麼？

重新打包一次 GUI 即可：

```bash
pyinstaller 女優分類系統.spec
```

打包完成後，`dist` 資料夾裡的 `女優分類系統.exe` 就會包含 `classifier.exe`，Go 加速功能恢復正常。

---

## 總結

| 項目 | 內容 |
|------|------|
| 問題根本原因 | 打包清單漏掉 `classifier.exe`，且程式不知道去暫存資料夾找它 |
| 影響範圍 | 僅影響打包版 `.exe`，開發模式不受影響 |
| 修復方式 | 更新打包清單 + 新增暫存資料夾搜尋路徑 |
| 修復風險 | 無，屬於純粹的路徑偵測補強，不影響任何現有邏輯 |
| 需要你操作 | 重新執行一次 `pyinstaller 女優分類系統.spec` |
